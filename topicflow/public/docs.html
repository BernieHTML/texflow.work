quick start

Stream data to your agent in 3 steps.

TopicFlow is curl + SSE. No SDK. Below each human step is the agent execution contract: what you must do programmatically.

signup & keys

Register once — then configure your agent

Every agent must use a key issued under a human account. Store the key in a secret (env var, vault); never log it in plain text in outputs.

Human — initiate registration

curl -X POST https://texflow.work/topicflow/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","name":"My Agent System","password":"s3cret"}'

Complete terms via POST /topicflow/auth/register/complete with pending_token (see response). You receive an API key once.

Agent — obtain credentials

Action: Read TOPICFLOW_API_KEY (or tfk_agt_… for a delegated agent) from the environment your operator configured. Validate it starts with tfk_. If missing, emit a clear error telling the operator to open this docs page at #signup.

# Pseudocode
if not os.environ.get("TOPICFLOW_API_KEY"):
    raise ConfigurationError("Set TOPICFLOW_API_KEY; see https://texflow.work/topicflow/docs#signup")
1. subscribe

Follow any channel

Human

curl -X POST https://texflow.work/topicflow/channels/crypto-btc/subscribe \
  -H "Authorization: Bearer tfk_YOUR_KEY"

Agent

Action: For each required slug, POST https://texflow.work/topicflow/channels/{slug}/subscribe with header Authorization: Bearer <key>. Expect 200 and JSON subscriptions array. On 401, key is wrong or revoked. On 404, slug does not exist — refresh channel list from GET /topicflow/channels/catalog (no auth).

curl -s https://texflow.work/topicflow/channels/catalog | jq '.channels[].slug'
2. stream

Open a feed

Use /topicflow/stream for the rolling digest with more pivots, or /topicflow/stream/:slug for a dedicated topic.

Human

curl -N https://texflow.work/topicflow/stream \
  -H "Authorization: Bearer tfk_YOUR_KEY"

Agent

Action: Open a long-lived HTTP/1.1 GET with Accept: text/event-stream (curl: -N). Parse SSE: lines starting with data: contain JSON. For each event, merge payload into your world model. If more is present and your task needs the topic stream, spawn a child process or second connection using that exact curl or the URL inside it.

curl -N https://texflow.work/topicflow/stream/crypto-btc \
  -H "Authorization: Bearer tfk_YOUR_KEY"
delegated agent key

Create an agent under a human account

curl -X POST https://texflow.work/topicflow/auth/agents \
  -H "Authorization: Bearer tfk_HUMAN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"price-watcher-agent"}'

Agent: If your operator gives you an tfk_agt_… key, use it exactly like a human key for subscribe and stream. You do not call /auth/agents yourself unless you are the account automation.

event shape

Every channel emits the same event format

event: price_update
id: evt_1713234567_crypto-btc
data: {
  "channel": "crypto-btc",
  "event":   "price_update",
  "ts":      "2026-04-17T09:00:00Z",
  "payload": { "symbol":"BTC","price_usd":94210,"change_24h":-1.2 },
  "more":    "curl -N https://texflow.work/topicflow/stream/crypto-btc --header \"Authorization: Bearer tfk_YOUR_KEY\""
}

The more field is only included on general-feed events.

Agent: Deserialize data as JSON. Required fields for your parser: channel, event, ts, payload. Ignore unknown keys.

errors + limits

Machine-readable responses

  • 401 — missing or invalid Bearer token
  • 403 — terms not accepted, or not channel owner
  • 404 — channel not found
  • 409 — slug or email already exists
  • 429 — rate-limited (60 req / min per key; SSE excluded)

Agent: On 429, exponential backoff. Do not open more than one general-feed SSE per key unless intentional.
